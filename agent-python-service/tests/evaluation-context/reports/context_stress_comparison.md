# 上下文压缩扩展压力评测结论

## 评测范围

- 数据：112 条高真实性合成记录，其中 110 条可回答事实、490 个标注信息单元。
- 历史：112 轮；固定窗口保留最近 6 轮。
- 模型：项目当前配置的 `qwen3.7-plus`。
- 策略：固定窗口、一次性摘要 + 最近原文、每 20 轮更新一次的滚动摘要 + 最近原文。
- 限制：数据是合成压力集，不是线上真实用户对话；每种模型策略只运行 1 次，不能评估随机波动。

## 核心结果

| 指标 | 最近 6 轮固定窗口 | 一次性摘要 | 6 次滚动摘要 |
|---|---:|---:|---:|
| 回答上下文估算 Token | 164 | 660 | 549 |
| 相对完整历史压缩率 | 91.6% | 66.2% | 71.9% |
| 信息单元保留率 | 20.0% (98/490) | 86.5% (424/490) | 81.2% (398/490) |
| 实体保留率 | 14.3% | 99.0% | 96.2% |
| 属性/约束保留率 | 24.3% | 77.1% | 70.0% |
| 全部标注均保留的事实 | 10.9% (12/110) | 40.0% (44/110) | 23.6% (26/110) |
| 核心实体—值关系完整率 | 10.9% (12/110) | 29.1% (32/110) | 49.1% (54/110) |
| 信息密度（单元/1000 Token） | 597.6 | 642.4 | 725.0 |
| 摘要调用输入/输出 Token | 0 / 0 | 3734 / 4067 | 7095 / 15674 |
| 摘要总耗时 | 0 秒 | 70.34 秒 | 272.03 秒 |

## 解释

1. 原来的 100% 是小样本效应。事实从 31 条增加到 110 条后，一次性摘要只保留 86.5% 的词面信息单元；进行 6 次滚动更新后进一步降到 81.2%。因此不能再声称摘要无损。
2. 摘要策略的主要收益真实存在：滚动摘要相对完整历史减少 71.9% 的回答上下文，同时比最近窗口多保留 300 个信息单元（398 对 98）。
3. 固定窗口并非“准确率必须为 0”。它完整保留最近 6 轮，所以仍保留 20.0% 的全部信息、10.9% 的完整事实；它只是对窗口外信息没有记忆。
4. 滚动摘要比一次性摘要更短、更密，但累计更新会损失属性细节：属性保留率从 77.1% 降至 70.0%，完整事实从 44 条降至 26 条。
5. 关系完整率和完整事实率衡量不同方面。前者只检查核心“谁—什么值”是否仍连在一起；后者要求该事实的所有标注约束都存在。滚动摘要更倾向于保留核心关系并删除重复业务措辞，因此出现关系完整率提高、完整事实率下降并不矛盾。
6. 更正样本的新值均被保留，但摘要和近期原文也出现旧值。自动规则把任何旧值出现都记为不安全，因此 0% 是保守下界，并不等价于 10 条事实都发生语义冲突；需要人工判断旧值是否处于“由旧值更正为新值”的正确语境。

## 当前判断

对这组压力数据，当前“摘要 + 最近原文”明显优于仅保留最近 6 轮：它以更多回答上下文换回大量长期信息，并且仍比完整历史短约 72%。但当前策略不是无损压缩，连续滚动尤其容易删掉属性和约束。上线结论应表述为“在合成压力集上改善长期信息覆盖”，不能表述为“完整保留上下文”或“必然优于所有固定窗口设置”。

下一阶段应使用经过授权的脱敏真实会话，按短、中、长会话分层，每个配置重复至少 3 次，并人工审查关系错误、否定错误、旧值冲突和无来源新增信息。
